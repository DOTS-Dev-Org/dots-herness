# Platform Parity — Bilinen Farklar

## Desktop shell (macOS referansıyla ilerletildi)
- Windows/WPF ve Linux/Avalonia artık MacOS ile aynı proje-öncelikli sınırı kullanır: arama, yeni konuşma, Pull Requests, Sites, Scheduled ve Plugins; Projects/Recent bölümleri; aktif proje konuşmaları; hesap/footer alanı.
- Sidebar ve Right Dock sürüklenebilir splitter ile açılıp kapanır; dock sekmeleri `Review`, `Terminal`, `Files` ve `Browser` olarak ortaklaştırıldı. Git çalışma ağacı, yerel terminal ve dosya önizleme iki masaüstünde de gerçek çalışma alanına bağlanır.
- Pull Requests, `origin` remote'unu GitHub/GitLab/Bitbucket URL'sine çevirerek açar. Sites, MacOS'taki Cloudflare Pages hedefini kullanır.
- macOS dock'u WKWebView, Windows/WPF WebView2, Linux/Avalonia ise WebKitGTK tabanlı NativeWebView kullanır. Üçünde de adres çubuğu, geri/ileri/yenile, sayfa durumu, dış tarayıcıya geçiş ve `native_browser` ajan aracı (ekran görüntüsü, JS, metin, tıklama ve yazma) vardır. Windows ve Linux derlemeleri geçti; bu macOS ortamında yerel WebView çalışma zamanı doğrulanmadı. Linux dağıtımı GTK3 ve WebKitGTK 4.1 (veya bulunan 4.0) runtime kitaplıklarını sağlamalıdır.
- Windows/Linux ortak git-worktree sandbox yaşam döngüsünü ve ayar arayüzünü kullanır. Linux ajan komutları ve dock terminali bubblewrap ile yalıtılır; Windows'ta eşdeğer süreç sınırı henüz yoktur, bu yüzden ajan `run_command` çağrıları güvenli biçimde kapalı kalır ve sandbox açıkken dock terminali devre dışıdır. Ayrıntılar aşağıdaki SandboxWorkspace bölümündedir.

## Tray / menü çubuğu varlığı
- Üç masaüstünde de süreç pencereye bağlı değildir: simge her zaman tepside/menu çubuğunda durur, pencere kapatıldığında uygulama çalışmaya devam eder (ajan run'ları, terminaller ve zamanlanmış görevler süreçle yaşar).
- Ortak ayar: `ui.closeToTray` (varsayılan açık). Açıkken kapatma pencereyi gizler; kapalıyken eski davranışa döner ve `ui.confirmBeforeExit` onay diyaloğu çıkar. Gerçek çıkış her iki durumda tray/menu „Quit", Cmd+Q veya Alt+F4 yolundaki onaya bağlıdır.
- macOS: `AppStatusItem.swift` `NSStatusItem` + `NSMenuDelegate` (menu her açılışta yeniden kurulur, dil değişimi yakalanır); `AppDelegate.windowShouldClose` → `orderOut`, `applicationShouldHandleReopen` + tray „Open window" → geri getirir. Template simge `Resources/TrayIcon{,@2x,@3x}.png`.
- Windows: `NotifyIcon` + `ContextMenuStrip` (aç/kapat balonu zaten vardı, menü eklendi), `ShutdownMode.OnExplicitShutdown`; `MainWindow.Closing` gizler, `Closed` gerçekten kapanınca `ExitApplication()` çağırır. İlk gizlemede bir kez balon (`ShowBalloonTip`) gösterilir.
- Linux: Avalonia `TrayIcon`/`TrayIcons` + `NativeMenu`, aynı explicit-shutdown + hide-on-close mantığı; gizlenince ilk kez `notify-send` bilgilendirmesi.
- Bilinen fark: Linux'ta simge XEmbed (Applet) ve StatusNotifierItem üzerinden çizilir; GNOME/WM'ler SNI ister ve AppIndicator desteği yoksa (veya Wayland'da dış arayüz izin vermezse) simge görünmeyebilir — pencere gene de gizlenir ve `notify-send`/Dock'tan geri açılır.
- Windows/Linux `AppModel.cs` ortak derlendiği için ayar tek yerde; macOS `AppModel.swift` + `AppModel+Settings.swift` aynı anahtarı okur.

## Subagents (explore)
- Beş istemcide de salt-okunur `explore` alt ajanı var: kendi context'inde tarar, ana konuşmaya yalnızca `## Findings / ## Unresolved / Status:` özeti döner; turda en fazla 3 alt ajan paralel, alt ajan başına 20 adım, 2000 karakter hedefi + tek kısaltma denemesi.
- Masaüstü ortak ayar: `agent.subagentsEnabled` (bool). Ayar hiç yazılmadıysa kullanım moduna uyar: Economy'de kapalı, diğerinde açık (`RouterController.subagentsEnabled` / `SubagentsEnabled`). Kapalıyken araç listeye girmez (şema token'ı yok) ve prompt'taki `explore` yönlendirmeleri de çıkar (`AgentBridge+Tools.swift`, `ProjectKnowledge.guidance(explore:)`, `WorkspaceFacts.Text(explore:)`).
- Mobil: `mobile/ios/Sources/ExploreTool.swift` ve `mobile/android/.../ExploreTool.kt` (`MobileExplore`). Ayar `herness.agent.subagentsEnabled`, varsayılan açık; mobilde Economy modu olmadığı için moda bağlı varsayılan yok. Alt ajan konuşmanın sağlayıcısında, adından seçilen en hafif modelde çalışır (`lightModel`: haiku/nano/mini/…); o model reddedilir ya da limiti dolarsa konuşmanın modeline düşer. Masaüstündeki "Keşif modeli" seçicisi mobilde yok.
- Bilinen fark: masaüstü yarıda kalan taramanın bulgularını `ExploreMemo` ile saklayıp aynı soruda devam eder; mobilde bu yok (kod içi `ponytail:` notu). Alt ajanın okudukları iki tarafta da ana run'ın yazma yetkisine sayılmaz (masaüstü ayrı ledger scope, iOS `ReadLedger.suppressed`, Android `SubagentReads`).
- Yazabilen alt ajan `delegate` (aynı `subagentsEnabled` anahtarına bağlı): `task` + `files` alır; `files` alt ajanın oluşturup değiştirebileceği tek yol kümesidir (dizin altını kapsar). Okuma serbest, atama dışına yazma reddedilir; dosya silemez, bildirilen `checks` dışında komut çalıştıramaz. Ana modele yalnızca `## Changes / ## Unresolved / Status:` raporu ve diskte doğrulanmış değişen dosya listesi döner. Konuşmanın kendi modelinde çalışır, 40 adım sınırı.
  - Çakışma kuralları: (1) aynı turdaki atamalar kesişemez, kesişen çağrı reddedilir; (2) alt ajanlar yazarken ana run'ın kendi mutasyonları (yazma/`run_command`) alt ajanlar bitene kadar bekler; (3) alt ajanın okuma/yazmaları ayrı ledger scope'unda tutulur, bu yüzden ana ajan alt ajanın değiştirdiği dosyayı yeniden okumadan yazamaz, alt ajan da yalnızca ana ajanın okuduğu dosyayı körlemesine yazamaz.
  - Doğrulama (`checks`, yalnızca masaüstü): ana ajan alt ajan başına en fazla 3 komut bildirir (build, tek test sınıfı, lint). Alt ajan yalnızca bunları `run_check` ile **numarasıyla** çalıştırır; komut satırını değiştiremez, `run_command` hâlâ kapalı. Sonucu host tutar: her check için `passed` / `FAILED` / `never run` / `not run again after the last edit` (geçtikten sonra dosya değişirse geçiş düşer); hepsi son düzenlemeden sonra geçmediyse araç sonucuna `[Unverified …]` eklenir. Aynı turdaki alt ajanların check'leri tek tek çalışır (aynı build dizininde iki derleme çakışmasın); `run_command`'ın 45 sn sınırı ve sandbox'ı aynen geçerli. Dosya silebilecek komut check olamaz, çağrı reddedilir.
    - macOS: ağ erişebilecek komut da reddedilir. Her check `run_command` gibi onaylanır (izin moduna göre; banner komutu gösterir). Çıkış kodu süreçten okunur (`WorkspaceTools.runCheck`), yerelleştirilmiş metinden değil. Uzak (SSH) çalışma konumunda `delegate` artık yerel diske dokunmaz, reddedilir.
    - Windows/Linux: her check başlamadan önce `run_command` onayıyla sorulur (komut önizlemede). Sonuç `NativeWorkspaceTools.CommandSucceeded` ile `RunCommandAsync`'in sabit İngilizce metninden okunur.
    - Mobil: `checks` yok. Telefonda `run_command` sanal kabuk ya da eşli masaüstüne iletim; güvenilir çıkış kodu dönmüyor. Doğrulamayı ana ajan yapar.
  - macOS `DelegateTool.swift`: turda en fazla 3 paralel; çağrı izin moduna göre bir kez onaylanır ve onay atama içindeki yazmaları kapsar; başka sohbetin yazma lease'i tutan dosyada beklemez, reddedip raporlar; yazmalar `memory.recordTool` ile kaydedilir. Plan modunda kapalı.
  - Windows/Linux `shared/DelegateTool.cs`: turda en fazla 3 paralel; bu istemcilerde `write_file`/`edit_file` zaten onaysız olduğundan `delegate` de onay istemez. `ReadLedger.Scope` (AsyncLocal) ve `WorkspaceWriteLeases` eklendi: ayrı sohbetlerin aynı dosyaya yazması ve yıkıcı komutların dosya yazımıyla çakışması iptal edilebilir bir lease bekleyişiyle sıralanır. macOS ile aynı `waitThenAsk`/`ask`/`waitOnly` politikaları, 10/30/60/120 saniyelik bekleme seçimi (varsayılan 30), bekleme kartı, bekleme bildirimi, bekletme/durdurma/atlama kararları ve ayarlar Windows WPF ile Linux Avalonia'ya taşındı.
  - Mobil `MobileDelegate` (`ExploreTool.swift` / `ExploreTool.kt`): onay gerektirir ve mobil run döngüsü tur başına tek onay işlediği için **sırayla**, turda bir alt ajan; paralel başlatma ve kardeşler arası kesişim denetimi yok. Android'de `write_file` ledger'a hiç bakmadığı için (3) yalnızca `edit_file` için geçerli.

## SandboxWorkspace
- `macos/DotsHarness/Sources/DotsHarnessCore/SandboxWorkspace.swift:11` + `AppModel.swift:75` `activeSandbox` macOS `git worktree`.
- iOS `mobile/ios/Sources/SandboxWorkspace.swift:11` + `LocalWorkspaceStore.swift:10` `activeSandbox` file-copy tabanlı soft sandbox — `HerNess/sandboxes/<hash>/<name>` izole kopya, `exit(merge:)` dosyaları geri kopyalar, `discard` siler. Branch `herness/sandbox-<name>` metadata. `ReadLedger` ve `agentFiles` sandbox root üzerinden çalışır, `HerNessMobileApp.swift:64` git client sandbox değişiminde yenilenir.
- Windows/Linux `shared/SandboxWorkspaces.cs` ve `AppModel.Sandbox.cs` üzerinden destek dizini altında `herness/sandbox-<name>` worktree oluşturur, listeler, geri yükler, merge eder veya atar. Başlangıçta origin'deki değişiklikleri korur ve sandbox'ı son commit'ten açar; merge öncesi origin dalını, temiz çalışma ağacını ve devam eden git işlemlerini doğrular.
- Çakışma olursa origin merge'ü geri alınır; çözüm sandbox içinde hazırlanır. Tam diff ve dosya listesi fingerprint ile önizlenir; onay, önizleme güncelken ve çözümlenmemiş işaret kalmadığında commit/merge yapar. Uygulama açılışında kurtarma, temizliği yeniden deneme ve conflict durumunu geri yükleme desteklenir; etkin sandbox sırasında MCP bağlantıları duraklatılır.
- Linux ajan komutları ve etkileşimli terminali bubblewrap ile host home ve proje belleğinden ayırır; yazma alanı sandbox worktree ve git metadata ile sınırlanır, ağ varsayılan olarak kapalıdır. Linux bubblewrap davranışı bu macOS ortamında canlı çalıştırılmadı.
- Windows iş akışını ve arayüzünü taşır ancak OS süreç yalıtımı henüz yoktur. Ajan `run_command` fail-closed kalır; sandbox açıkken etkileşimli terminal de engellenir. Windows'ta gerçek ajan komut yalıtımı doğrulanmadan macOS güvenlik paritesi sağlandı sayılmamalıdır.

- Windows/Linux'ta sistem OpenSSH anahtarı/agent'i gerekir; macOS'un parola ile anahtar kaydı ve Keychain parola saklama akışı henüz taşınmadı. SSH desteğinin derlendiği doğrulandı; canlı uzak host ve host-key değişimi senaryosu bu görevde çalıştırılmadı.

## Multi-Account Provider Priority & Conversation Affinity
- Üç masaüstü: sağlayıcı ailesi önceliği + sohbet–hesap affinity.
  - `RouterController.orderedRoutes` (`RouterController.swift`) aktif hesapları cooldown → kalan kota (`accountUsage`) → `priority` sırasıyla dizer; `send`/`complete` yeni `preferredAccountID` parametresi ilk turda seçilen hesabı sonraki turlarda sabitler (prompt-cache).
  - Prompt-cache breakpoint'i fiilen konuyor (`NativeAgentClient`): Anthropic gövdesinde son `system` bloğu, son tool ve son mesaja `cache_control: {"type":"ephemeral"}`; OpenAI/Responses gövdesinde `prompt_cache_key` (`AgentBridge.cacheKey` = `herness:<projectID>:<model>:…`). Usage parse'ı Anthropic'te `cache_read_input_tokens`/`cache_creation_input_tokens`, OpenAI/Responses'ta `*_tokens_details` alanlarını `AgentUsage.cachedTokens`/`cacheWriteTokens`'a yazar. Gemini'de açık `cachedContent` yok — implicit caching + affinity pini yeterli (kod içi `ponytail:` notu).
  - `Conversation.stickyAccountID`/`stickyModelID` (`ConversationStore.swift`) + `StoredProviderAccount.cooldownUntil` (`ProviderStore.swift`) persist edilir; `AgentBridge` run başında `router.affinityAccountID` ile doğrular, başarılı turdan sonra yazar. Invalidation: model/sağlayıcı değişimi veya 429 cooldown.
  - Kullanım verisi yalnızca `claude` sağlayıcısı için canlı çekilir (`ClaudeUsageService` → `RouterController.refreshAccountUsage`); diğer abonelik sağlayıcıları `remainingFraction = nil` (bilinmeyen) kalır, `priority` sırası + cooldown korur. Yükseltme yolu: `NativeAgentClient` yanıtından `x-ratelimit-*` başlıklarını yakalamak.
  - Settings › Providers: sağlayıcı grubu başlıklarında sürükle-bırak + ↑/↓ butonları → `RouterController.reorderProviders` (`providerIndex*100 + hesapIndex` → `priority`). `RouterCatalog.groups(from:)` grupları `priority`'ye göre sıralar.
- Windows/Linux: `NativeProviderAccount.Priority` (`shared/NativeProviderRouter.cs`) yönlendirmede kullanılır. Settings içindeki ↑/↓ denetimleri sağlayıcı ailelerini yeniden sıralar; her ailenin hesap sırasını koruyup `priority = providerIndex * 100 + accountIndex` olarak kalıcılaştırır.
- Windows/Linux: `Conversation.StickyAccountId` (`SessionProjector.cs`) başarılı turda kaydedilir ve sonraki turda `preferredAccountId` olarak router'a verilir. Hesap/model/protokol değişince `ContextRouteIdentity` yeniden hesaplanır; açık limit devamı son sınırlayan hesabı dışlar.
- OAuth kataloğu farkı: Windows/Linux artık ChatGPT ve Claude browser OAuth'a ek olarak `grok-cli` / Grok Build cihaz kodu akışını, token yenilemeyi ve Responses taşımasını sunar. xAI cihaz kodu uç noktaları macOS `providers.json` kaydından taşındı; abonelikle canlı giriş bu ortamda doğrulanmadı. xAI'nin yayımlanmış REST belgeleri Responses API'nin OpenAI uyumlu olduğunu doğrular, ancak bu abonelik OAuth akışını belgelemez.
- Google Code Assist ve Antigravity OAuth akışları macOS kataloğunda yer alır ancak paketli `providers.json` içindeki iki `clientID` alanı boş olduğundan tamamlanabilir varsayılan bir giriş akışı yoktur. Windows/Linux bu geçersiz varsayılanı kopyalamaz; kullanıcıya ait geçerli istemci bilgisi eklenmeden OAuth paritesi sağlanmış sayılmaz.
- Windows/Linux sağlayıcı kataloğuna macOS'ta bulunan DeepInfra, OpenCode Zen, OpenCode Go ve Z.ai Coding Plan API uçları eklendi. OpenCode'un `x-opencode-client` ve Grok Build'in istemci başlıkları model isteği ile model keşfinde ortak uygulanır.
- Kullanım verisi: macOS ve Windows/Linux ChatGPT OAuth `/wham/usage` ile Claude OAuth kullanımını (5 saat/hafta, reset zamanı ve varsa reset hakkı) bellekte tutar; Windows/Linux 60 saniyede yeniler ve tray/account alanında gösterir. Claude OAuth PKCE oturumu ve Anthropic API başlıkları macOS uygulamasındaki akıştan taşındı; kullanım endpoint'i erişilemezse düşük maliyetli başlık probe'u denenir. Endpoint gövde/header biçimleri canlı abonelikle doğrulanmadı; olmayan yüzde bilgisi sıfır gösterilmez, bilinmeyen kalır. W/L router kullanım kotasına göre alternatif hesapları sıralar, açıkça seçili hesabı ve sohbetin sticky hesabını öncelikli tutar. Reset düğmesi sadece açık onaydan sonra Claude Usage sayfasını açar; reseti uygulama tüketmez.

## Plugin composition & lifecycle
- Çekirdek: `CompositionLoader.loadHost` (`macos/.../DotsHarnessCore/AppModel.swift`, `linux/.../DotsHarnessCore/AppModel.cs`) artık katalogdaki her plugin'i (builtin + kurulu) id-sıralı olarak mount edilen `CompositionDocument`'a ekler. `host.patch.yml` yalnızca override katmanı (sıralama, `config` merge, explicit `disable/enable`). Eski davranış: sadece `dots.vision-fallback` özel-case'i mount oluyordu. Her iki platformda paritedir.
  - **`isolate:` şu an inert.** `PluginHost.mount`/`Mount` `isolate` anahtarını yalnızca `plane: session` dokümanında onurlandırıyor; bu yol her zaman `.host` düzlemli doküman kuruyor, dolayısıyla `host.patch.yml` içindeki `isolate` parse ediliyor ama etkisi yok. Gerçek session izolasyonu için konuşma başına ayrı `plane: session` `PluginHost` gerekir (opsiyonel yükseltme).
- `install_plugin` agent tool'u (`InstallPluginTool.swift`) ve üç platformdaki katalog yalnızca native manifest + derlenmiş library kabul eder; JavaScript ve manifest-only/declarative pluginler artık yüklenmez. Kullanıcı kaynakları Marketplace/CI dışından çalıştırılmadan önce untrusted tutulur.
- macOS Settings › Plugins/Marketplace — signed `.dotsplugin` indirir, hash + DOTS Ed25519 imzasını doğrular, native-code uyarısı sonrası trusted mount eder; HerNess OAuth/email oturumu ile plugin publish, immutable release geçmişi, build durumları, source preview ve soft-unpublish yönetilir. Yerel fork upstream'den ayrı kimlikle saklanır ve otomatik ezilmez.
- Windows WPF ve Linux Avalonia aynı public `https://dots.net.tr/harness/registry.json` sözleşmesini kullanır; platform/architecture artifact durumunu gösterir, imza/hash doğrulamasından sonra açık native-code onayıyla mount eder. HerNess email/password oturumu, token yenileme, owned-plugin/release durumları, onaylı unpublish ve native publish akışı da iki istemcide vardır. Yayın penceresi plugin klasörünü seçer, IR/native kaynak önizlemesi, SemVer, SPDX lisansı, public/private kaynak görünürlüğü ve macOS ile aynı platform hedeflerini sunar; kaynak paketi kullanıcı klasörünün kopyası üzerinde oluşturulur. Üçüncü taraf plugin raporlama; yerel fork oluşturma, kaynak klasörünü açma, `.dotsplugin` dışa aktarma, upstream sürümünü işaretleme ve güven onayından sonra etkinleştirme/kaldırma da taşındı.

## Agent Runtime
- Android device automation: macOS, Windows/WPF, and Linux/Avalonia expose the same `android_emulator` actions over the Android SDK (`adb`/`emulator`): device/AVD discovery, boot/shutdown, install/launch/terminate, URL opening, screenshots, input, and error logs. Discovery is read-only; device-changing actions require approval. The Windows/Linux `device-verification` skill now describes the tools those clients actually provide. `ios_simulator` remains macOS-only because the simulator and `xcrun simctl` are Apple-hosted tools.
- Follow-up suggestions: after a successful turn, Windows/Linux now generate the same private one-line next-step suggestion as macOS, show it only for its conversation while the composer is empty, and let the user accept it with Tab or the composer button.
- Context admission: when a route change would require compaction, Windows/Linux now ask before sending the request, show the target context budget and the model that will summarize, and stop before the provider call if declined. A non-interactive run continues without waiting for a UI response.
- Context/cache usage: the Windows/Linux composer shows the model context window and estimated input composition (conversation, system prompt, native tool definitions, and MCP definitions), plus measured cache hit, verified prefix reuse, measurement coverage, cold/expired/changed counts, cache writes, fresh input, unknown reuse, largest loss reason, request latency, and request preparation time. Cache history is grouped across loaded conversations by provider, endpoint, account, protocol, and model, with up to 100 recent events per route. First-token latency is not reported because these clients currently buffer response bodies before parsing them.
